## 1. 应该迁移的核心思想

### 1.1 论文实际解决的是训练经验的分配问题

在复杂机器人任务中，只从完整任务起点出发，随机策略可能长时间看不到成功。通过仿真重置，可以让机器人从一些有用的中间状态开始，例如已经接近插孔，或者物体已经位于目标上方。

但配置多样并不等于数据有效。在同一个训练阶段，有些配置已经熟练，有些配置几乎无法成功，也有一些配置能成功一部分、仍有明显提升空间。若每个配置都分配相同数量的 episode，大量采样可能集中在前两类。

**【原文，§3.1–3.3】SGS 使用经验成功率作为低成本的在线信号，让训练更多地覆盖当前能力边界附近的配置。** “当前能力边界”由实际执行表现确定，不要求预先按距离、地形高度或任务阶段给所有配置排好难度顺序。

SGS 的闭环是：

```text
固定、可重复访问的任务配置库
           ↓
按各配置近期成功率计算采样概率
           ↓
在 episode 重置时选择配置
           ↓
当前策略与仿真环境交互，PPO 正常学习
           ↓
把本次 episode 的真实成功/失败归还给它的起始配置
           ↓
更新该配置的成功率历史和后续采样概率
```

随着共享策略学会相关技能，某些原来困难的配置可能开始成功，进而得到更多练习；某些已经掌握的配置被减少采样，但仍然保留重访机会。

### 1.2 为什么“中等成功率”是有依据但不保证最优的代理信号

**【推导】** 对二值结果，伯努利方差为 $p(1-p)$，在 $p=0.5$ 时最大。这能帮助理解“有成功也有失败”的配置为什么可能提供更有区分度的反馈。但 SGS 的采样公式不是由策略梯度最优分配定理推导出来的。

需要保留以下区别：

- 成功率中等，表示近期执行结果有成有败；不等价于该配置的真实学习进度最大。
- $p_i$ 同时受任务难度、探索噪声、策略能力和环境随机性影响。
- 一个不可消除随机性很大的配置，也可能长期表现为中等成功率。
- 论文的运动默认目标成功率是 $0.66$，装配是 $0.5$；不存在所有任务都应严格以 $0.5$ 为目标的结论。

因此，迁移时应保留这个经验分配原则，并用固定评估集检验效果，而不能把它解释成已有严格性能保证。

### 1.3 配置库和 SGS 各自承担什么

**配置库提供有机会学到任务的起点；SGS 决定这些起点当前应被练习多少次。**

如果所有可用配置对初始策略都完全不可解、始终没有成功，则所有成功率相同，SGS 无法凭空产生差异化信号。如果关键中间状态根本不在配置库中，调采样温度也不能补上这部分覆盖。

原文装配消融给出了直接证据：在测试的 rod-in-hole 设置中，移除 Near-Goal 后，保留的 Stable Grasp 和 Reaching 的平均成功率均为 0；完整配置库下，Reaching 达到 96.0%。这是三次训练种子的特定实验结果，不是所有任务的普遍定理。【原文，附录 B.3，表 4】

### 1.4 第一版实现的范围

| 层次 | 第一版需要做的事情 | 是否属于 SGS 核心 |
|---|---|---|
| 任务配置 | 建立固定配置库和稳定的配置编号 | 是 |
| 结果统计 | 保存每个配置近期的二值 episode 结果 | 是 |
| 重置采样 | 根据成功率计算 Beta 形权重，再做带温度的类别采样 | 是 |
| 策略学习 | 沿用已有 PPO 训练 | SGS 使用 PPO，但不提出新的 PPO 损失 |
| 观测和动作 | 保留可解决该任务的既有设计 | 任务依赖 |
| 奖励 | 在相同奖励下先验证采样变化 | 任务依赖；原文采用成功奖励与较小正则项 |
| 网络、视觉蒸馏、控制器 | 按目标系统保留或适配 | 不属于采样器本体 |
| 大规模并行 | 在基础功能可靠后扩展 | 原文的重要实验条件，不是调用 SGS 的前提 |

## 2. 配置的定义与配置库构建

### 2.1 配置的粒度

**【原文，§3.1】** 配置由初始状态、目标和环境条件构成。本文记为

$$
c_i=(s_{0,i},g_i,e_i),\qquad i=0,\ldots,N-1.
$$

这里使用 $c_i$，避免把论文中的配置符号 $\tau_i$ 与轨迹混淆。

**【迁移设计，本仓库】** 目标固定为“抓取 sugar_box，抬升并连续保持”，没有装配目标座。一个配置 ID 对应一个具体起点及台面运动设置，而不是一个物体类别或抓取候选编号。应保存或能确定重建：

| 内容 | 本仓库对应状态 |
|---|---|
| 机器人初态 | 底座位置/姿态、关节位置/速度、夹爪开度；原始起步使用足底近地的腿部姿态与默认机械臂姿态 |
| 物体与桌面 | sugar_box 的 root 位姿/速度、台面高度、桌子初始位置/姿态 |
| 运动参数 | `vel_line_forward_y_level02`、`lin_circle_select`、`vel_angular_yaw`；相关运动计数按统一规则初始化 |
| 控制参考 | `curr_ee_goal_cart`、`curr_ee_goal_orn_rpy` 和相容的夹爪目标，尤其是临近抓取与已到达抓取位姿初态 |
| 固定元数据 | 对象/资产、名义 `init_height`、成功标准、低层控制器和配置库版本 |
| 分析标签 | reset 家族，仅用于诊断，不代替具体配置 ID |
| 接地审计 | 保存帧足部碰撞几何和检查元数据；只检查大致接地，接触力只作诊断 |

现有原始 reset 可用距离、yaw、桌高、夹爪偏移和运动参数重建；临近抓取与已到达抓取位姿还需要保存对应的机械臂关节、夹爪关节和控制目标。第三类保存随机开度，不假定物体已形成有效抓持。网络使用的 30 个候选抓取位姿可帮助构造初态，但不自动等于 30 个 SGS 配置。

**SGS 的统计单位应是具体配置，不只是“近目标”“抓取”“接近”三个类别。** 一个类别内部可能同时有很容易和很困难的状态，合成一个成功率会丢失 SGS 所需的区分度。

配置编号通常只供采样器和日志使用，不必作为策略输入。策略需要的是足以理解任务的观测和目标信息；隐藏目标、隐藏地形等造成的观测问题，不会由配置编号表自动解决。

### 2.2 原文装配配置库

**【原文，附录 A.2】** 每个装配任务分别训练策略，预先构建 32,768 个经过碰撞检查的配置，三种 reset 家族大体均衡。运动任务则使用一个跨地形的共享策略。

| 家族 | 原文构造方式 | 对学习的意义 |
|---|---|---|
| Near-Goal | 把物体置于装配路径上，通过逆运动学把末端放在任务相关抓取点附近，并扰动位置、姿态、夹爪开度 | 提供完成任务末段的可达起点 |
| Stable Grasp | 物体位于目标上方，比 Near-Goal 的高度更高，采用类似抓取设置并扰动夹爪开度 | 覆盖搬运、对准和接触装配 |
| Reaching | 在工作空间内采样物体姿态，末端通过逆运动学与抓取坐标系对齐，夹爪开度随机 | 不保证已经抓稳，可能需要拾取、重抓和完成任务 |

两点容易误读：

1. 原文 Reaching 不是简单地把末端放在远离物体的位置；它包含抓取未稳定、物体可能掉落的情况。
2. Near-Goal 根据任务几何构造。螺纹装配的路径需要耦合转动和轴向移动，不能统一替换成“沿直线靠近目标”。

rod-in-hole 的原文路径比例范围为 $[0,1.1]$，0 表示完全插入，大于 1 可以覆盖略微脱离的状态。其他任务的比例和路径不同，不能照搬这个区间。【原文，附录 A.2】

### 2.3 本仓库简化版如何建立配置库

**【迁移设计，v5】** 三类起点在训练开始时同时开放，SGS 按具体配置的近期成功率决定抽样概率，不按阶段解锁。

| 家族 | 本任务初态 | 主要练习 |
| --- | --- | --- |
| `full_task`：完整任务起步 | 正常重置，物体在桌上，底盘按 YAML 放置，机械臂默认姿态，足底大致接地 | 接近移动目标，衔接整条任务链 |
| `pregrasp`：临近抓取 | 物体仍在桌上，夹爪张开；用 IK 将末端放在候选抓取位姿前的可调距离 | 跟踪、最终对准、闭爪和抬升 |
| `at_grasp`：已到达抓取位姿 | 物体仍在桌上，末端用 IK 对齐候选位姿，夹爪开度在可调范围内随机 | 从不同接触/开度状态学习闭爪、抓取、抬升和保持 |

三类分别设置世界 x/y 有符号间隔和相对物体方向的朝向偏角；`x = object_x - base_x`，`y = object_y - base_y`，偏角为 `wrap(base_yaw - atan2(y,x))`。完整任务保持默认机械臂关节角。

临近抓取沿候选抓取姿态的 local +x 反方向后退，末端方向沿用候选姿态。`pregrasp.ee_approach_distance_range_m` 设置后退距离；最初要求为 5–10 cm，当前 YAML 保留用户已改成的 5–15 cm。三类的底盘范围也保留用户当前设置，实际取值以 [sgs_bank.yaml](../DQ_high-level/data/cfg/sgs_bank.yaml) 为准。范围在短物理刷新后的实际保存状态上复核；非零宽范围不向外自动放宽，固定值保留毫米/角度容差。

第三类的 `at_grasp.gripper_opening_range` 是归一化开度，0 为闭合、1 为全开，映射到 URDF 关节上下限，默认 `[0.0, 1.0]`。同时保存实际关节位置和相容控制目标。该类没有预先抬升，也不要求物体已经夹稳。旧 `grasped_before_lift.object_lift_height_range_m` 不再适用。

**三类只要求足底大致接地。** 按四脚碰撞球半径 0.04 m 计算足底高度，允许相对地面 **[−0.005, 0.020] m**；不以持续接触力、承重脚数、底盘静止速度或稳定站立时间为准入条件。足部视觉球半径仅 0.03 m，画面中的细小间隙不等于碰撞几何悬空。

构造流程简化为：

```text
选择家族，采样该类 YAML 参数
    → 正常任务重置，按足部几何校正底盘高度
    → 必要时用 IK 直接设置机械臂，设置夹爪开度和控制目标
    → 短物理刷新，检查参数范围、关节限位、碰撞与足底近地
    → 保存实际状态到固定缓冲区，分配稳定 configuration_id
```

**不再执行逐条完整抓取、抬升、跨环境保持或松爪掉落验证。** 论文附录 A.2 披露了 IK、位姿与夹爪随机化及碰撞检查，并未要求这些额外抓取脚本。取消它们是为了保留多样初态并降低离线构库成本；SGS 会利用策略训练中的真实成败更新各配置概率。可达性与碰撞筛选仍可能使最终距离/开度分布不均匀，不能保证任何 YAML 设置都能收齐。

碰撞检查需要排除明显不合法接触，允许足地接触与合理的夹爪物体接触。第三类随机开度可能产生接触，也可能尚未抓住；不要把“未抓稳”直接作为拒绝入库的条件。

桌高、Level02 台面运动和统一任务目标沿用原教师设置。所有起点在保存时物体仍处于原桌面支撑高度，`pick_counter`、`episode_success` 和抬升成功标志从零开始。`init_height` 保留名义物体高度；不能把“到达候选位姿”或“闭合夹爪”记为终局成功。训练仍要求抬升到任务高度并连续保持 15 步。

v5 元数据使用 `validation_profile: geometry_v1`，声明 `feet_near_ground: true`、`collision_checked: true`、`passed: true` 和 `object_attachment: false`，保存 YAML 快照与指纹。训练从这个固定缓冲区选择具体 ID，再批量恢复 root/DOF/控制目标；GPU 训练重置不重复构库过程。重置要同步更新物理状态、观测缓存并清空该回合历史，不能只改画面中的位姿。

v1/v2 曾因重置后过早保存而出现约 8 cm 真正悬空；v3/v4 加入严格站立和抓持筛选后又产生高构库成本。v5 保留防止明显悬空的足底几何检查，同时移除用户不需要的站稳和抓稳要求。**旧版本第三类语义不同，不能把旧库标记为 v5 继续使用。** 历史记录保留在使用说明。

在 `dqwbc` 环境、`DQ_high-level` 目录运行：

```bash
python build_sgs_bank.py --device cuda:0 --num-envs 1024 \
  --per-family 512 --seed 43 --max-batches 512 \
  --reset-config data/cfg/sgs_bank.yaml --output data/sgs/sugar_box_v5.pt
```

三类各 512 条，共 1536 条。收齐后保存，不足时报告失败，不复制样本补齐。一次构建后可多次训练；修改 YAML 后另建新库，uniform 与 SGS 对照始终使用同一文件和指纹。

教师命令增加 `--sgs_mode sgs --sgs_bank data/sgs/sugar_box_v5.pt`；均匀对照为 `--sgs_mode uniform`。采样器按全部具体配置计算概率，不是只给三个类别分配三个权重。完成 episode 后，把最终成功/失败归还给该回合的起始配置 ID。

随机预览每类 3 条：

```bash
python visualize_sgs_bank.py --device cuda:0 --headless \
  --bank data/sgs/sugar_box_v5.pt --samples-per-family 3 --seed 43 --steps 8 \
  --output ../doc/sgs_preview/v5_random_seed43
```

预览首帧只推进渲染所需的 5 ms，显示脚底间隙及实际/目标归一化开度。默认保留库中的随机夹爪目标；交互预览按 `O` 才人为开闭，按 `R` 恢复。接触力作为诊断，不宣称已经稳定站立。短时物理响应不等同于训练后的教师行为。

### 2.4 固定配置和本仓库随机化的关系

**【迁移设计】** 可以选择两种语义，但必须固定其中一种：

- 一个 ID 对应完整确定的初始配置和环境参数；
- 一个 ID 对应固定的名义配置，以及固定的条件随机化分布。

第二种情况下，$p_i$ 估计的是该名义配置在随机化条件下的平均成功率。传感器噪声等不一定都要拆成新 ID，但必须明确哪些变化包含在该条件分布中。

本仓库初版选择第二种语义，保留既有随机化：质量、COM、摩擦、部分控制参数等在环境槽之间不同；`rand_control` 每个高层步采用全体环境共享的随机 7/8 个低层循环。bank 固定名义初态和运动设置，不承诺确定性轨迹回放，也不把这些已有扰动重新扩展成巨大配置表。

若训练途中系统性改变重力、摩擦或成功阈值，同一 ID 的含义会发生变化。需要记录版本或课程阶段，并决定如何处理旧历史，不能把它当成同一个稳定条件。

### 2.5 配置库规模与并行环境数量分开设置

记：

- $N$：配置库条目数；
- $E$：同时运行的环境数量；
- $H$：每个配置的历史窗口长度。

它们是不同概念。一个配置可以同时被多个环境抽中；一个环境下一次 episode 可以换到另一个配置。

原文装配 $N=32,768$，不意味着迁移时必须开 32,768 个环境。原文运动配置数为

$$
13\times2\times10\times20\times20=104,000,
$$

分别对应地形类型、种子、级别、起点和目标点。【原文，附录 A.1】

若训练预算较小，应先选能够被反复访问的配置库规模。假设训练完成 $B$ 个 episode，均匀采样下每个配置平均只有 $B/N$ 次记录；$N$ 过大时，成功率统计很难及时反映当前策略。

**【迁移设计，本仓库初版】** 暂定 $N=1536$，三类各 512 条；$E=5000$ 沿用教师默认设置，$H=100$ 沿用论文。1536 是初版工程规模，不是论文结论。三类在库中各占三分之一，不要求训练回合始终各占三分之一；SGS 按全部具体配置的近期成功率进行全局采样，5000 个环境可以有放回地共享这些配置。

## 3. 成功率统计：先保证每一个结果归属正确

### 3.1 滚动窗口

**【原文，§3.2、附录 B.2】** 每个配置维护最近 $H=100$ 次二值结果，使用环形缓冲区保存。

对配置 $i$，设窗口中已有 $n_i\le H$ 次有效记录：

$$
h_i=(y_{i,1},\ldots,y_{i,n_i}),\qquad y_{i,j}\in\{0,1\}.
$$

对非空历史，采用：

$$
p_i=\frac{1}{n_i}\sum_{j=1}^{n_i}y_{i,j}.
$$

窗口按“该配置的有效 episode 次数”滚动，不按全局训练步数滚动。一个很久没有被访问的配置，其 100 条记录可能来自相当旧的策略。

### 3.2 空历史和未满窗口的明确约定

**【未披露】** 论文说明使用最近 $H$ 次结果，图 7 展示训练初期均匀采样，但没有充分给出空历史的数值回退、早期窗口填充等代码细节。

本文参考实现采用以下**【迁移设计】**：

- `count[i] == 0` 时，在计算采样权重时暂用 `p_init = 0.0`；
- 所有配置初始采用相同回退值，因此初始采样严格均匀；
- 有真实记录后，按真实记录数量计算均值；
- 未填满的槽位不作为失败参与分母；
- 日志保留“未知”标记，不把空历史报告为真实的 0% 成功率。

用 $p_{\mathrm{init}}=0.5$ 也能让初始分布均匀，但第一次收集数据后，它会相对优待仍未访问的配置。因此这两个初始化在后续行为上不等价。比较实验应固定初始化约定。

一个容易遗漏的现象是：只访问过一次的配置，其估计只能为 0 或 1；SGS 的权重不会仅因为“第一次成功”就立刻最大。只有后续记录中逐渐出现成败混合，才可能接近权重峰值。

### 3.3 一条什么样的结果可以更新历史

| 事件 | 是否更新 SGS 历史 | 记录内容 |
|---|---|---|
| 完成规定任务，episode 正常结束 | 是 | 1 |
| 真实任务失败并结束 | 是 | 0 |
| 达到规定的尝试时限，尚未完成任务，随后重置 | 是 | 0 |
| PPO 本次 rollout 收集到固定步数，但 episode 继续 | 否 | 不产生新 episode 结果 |
| 评估环境结束 | 不写入训练 SGS 表 | 单独统计评估指标 |
| 初始化重置，还没有执行过任务 | 否 | 无结果 |
| 仿真崩溃、人工取消、无效状态导致的非任务中断 | 按预先规定的异常策略处理 | 建议独立记录，不冒充普通任务失败 |

以上异常处理是**【迁移设计】**。它必须与实际环境语义一致。

成功标志应来自任务环境的权威判定，不能通过总 reward 是否大于某个值来猜测。若成功需要保持一定时间，应在满足保持条件后才判为成功。若环境允许成功后继续运行，需要预先定义“episode 成功”的汇总规则。

SGS 的二值成败与 PPO 的 bootstrap mask 是两个不同问题。一个达到任务时限的尝试可以给 SGS 记 0，而 PPO 是否 bootstrap 仍取决于该环境将时间限制定义为真正终止还是采样截断。

**【迁移设计，本仓库的权威标签】** 直接复用 [_reward_pick_up](../DQ_high-level/envs/reward_vec_task.py) 已有的 `episode_success`，在 reset 清零前读取。普通训练下：

- `lifted_object` 要求 `cube_z - table_heights - init_height > 0.20`，且物体到末端距离小于 0.20 m。
- 该条件连续满足 `hold_steps=15` 个高层步才锁存成功；sugar_box 的 `init_height=0.045` m，故其物体 root 高度需高于台面 0.245 m。
- `lifted_now` 是另一条掉落检测用判据，不能替代这个保持成功标签。
- 现有 `success_counter / episode_counter` 用于累计日志，不可直接作为各配置的近期成功率。

几何条件位于 [B1Z1PickMulti.check_termination](../DQ_high-level/envs/b1z1_pickmulti.py)。当前 eval 分支会抬起即终止；第 8 节要求主评估继续执行到保持条件满足。当前 [wrapper](../DQ_high-level/utils/wrapper.py) 将结束统一返回为 `terminated`、`truncated` 为零；初版沿用这条 PPO 接口，不因新增 SGS 改写 bootstrap 规则。

### 3.4 数据结构

| 字段 | 形状 | 含义 |
|---|---|---|
| `history` | `[N, H]` | 0/1 记录，建议用 uint8 或 bool |
| `count` | `[N]` | 已使用槽位数，最大为 H |
| `head` | `[N]` | 下一次写入位置 |
| `success_sum` | `[N]` | 当前窗口成功次数 |
| `visits_total` | `[N]` | 累计有效 episode 数，诊断用途 |
| `last_seen` | `[N]` | 最近一次更新的步数或策略版本，诊断用途 |
| `active_config_id` | `[E]` | 各环境当前 episode 来自哪个配置 |
| `episode_serial` | `[E]` | 区分同一环境的不同 episode，防止重复上报 |

收到一个结果后，环形更新为：

1. 找到 `head[i]`。
2. 窗口已满时，从 `success_sum[i]` 减去即将被覆盖的旧结果。
3. 写入新结果，并加到 `success_sum[i]`。
4. 更新 `count[i]` 与 `head[i]`。
5. 更新该配置的成功率和采样权重。

不要只累加终生成功/失败次数替代滚动窗口。终生平均会让训练早期的大量失败长期压住后来已经变得可学的配置。

## 4. 采样公式：按正文和附录共同实现

### 4.1 完整公式

为避免与时间步混淆，用 $p^\star$ 表示论文中的目标成功率 $t$，用 $T_s$ 表示采样温度。

**【原文，式 (1)、式 (2) 与附录 B.2】**

$$
w_i=(p_i+\varepsilon)^{\kappa p^\star}
    (1-p_i+\varepsilon)^{\kappa(1-p^\star)}.
$$

附录中的实现还包括：

$$
\widetilde w_i=\max(w_i,\varepsilon),\qquad
\ell_i=\log(\widetilde w_i+\varepsilon),\qquad
T_{\mathrm{eff}}=\max(T_s,1).
$$

最终概率：

$$
q_i=\frac{\exp(\ell_i/T_{\mathrm{eff}})}
{\sum_{j=0}^{N-1}\exp(\ell_j/T_{\mathrm{eff}})}.
$$

给需要重置的环境独立、有放回地采样配置：

$$
c_{\mathrm{next}}\sim\operatorname{Categorical}(q_0,\ldots,q_{N-1}).
$$

注意区分三个量：

- $p_i$：某个配置的经验成功率；
- $w_i$：该成功率经过核函数得到的分数；
- $q_i$：归一化后，下一次重置抽中该配置的概率。

### 4.2 Beta 形核的正确含义

核函数对应 $\mathrm{Beta}(1+\kappa p^\star,1+\kappa(1-p^\star))$ 的未归一化形状。实际操作是在每个已知 $p_i$ 上计算一个权重。

因此：

- 不需要随机抽取一个 Beta 变量作为下一个成功率；
- 这里没有用 Beta 后验做贝叶斯成功率估计；
- 原文直接使用未归一化的 Beta 形核，不需要计算 Beta 分布的归一化常数；
- 对零成功率和满成功率配置仍保留非零概率；
- $p^\star$ 是核的目标位置，不是“只接受这个成功率”的筛选阈值。

在忽略 $\varepsilon$ 和权重下限时：

$$
q_i\propto
p_i^{\kappa p^\star/T_{\mathrm{eff}}}
(1-p_i)^{\kappa(1-p^\star)/T_{\mathrm{eff}}}.
$$

这说明集中度和温度通过其比值共同影响分布形状；配置接近 0 或 1 时，仍应回到包含数值保护的完整公式。

若保留附录中的绝对权重下限和加 $\varepsilon$，先改用归一化 Beta 密度再做保护，并不严格等价于原式。因此实现时应直接按原文计算 $w_i$。

### 4.3 原文默认参数

| 参数 | 装配 | 运动 | 作用 |
|---|---:|---:|---|
| 配置数 N | 32,768 | 104,000 | 配置覆盖和统计粒度 |
| 历史长度 H | 100 | 100 | 近期表现的平均窗口 |
| 目标成功率 $p^\star$ | 0.5 | 0.66 | 希望重点覆盖的成功率位置 |
| 核集中度 $\kappa$ | 1 | 5 | 越大越集中于目标附近 |
| 温度 $T_s$ | 2 | 2 | 越大越平缓，附录限制不低于 1 |
| $\varepsilon$ | $10^{-4}$ | $10^{-8}$ | 极端成功率与权重的数值保护 |

这些参数来自 §3.2、附录 B.2。任务配置数是原实验设置，不是迁移必须满足的常数。

### 4.4 装配默认分布比“只选中等难度”平缓得多

**【推导】** 代入装配参数，并忽略数值保护：

$$
w_i\approx[p_i(1-p_i)]^{1/2},\qquad
q_i\propto w_i^{1/2}\approx[p_i(1-p_i)]^{1/4}.
$$

因此，直接使用 $\sqrt{p_i(1-p_i)}$ 归一化，会漏掉原文温度步骤，得到更集中的分布；直接使用 $p_i(1-p_i)$ 又是另一种分布。

下表按附录完整公式计算，给出单个配置相对 $p=0.5$ 配置的采样权重。不是某个实际配置库的绝对概率。

| 成功率 p | 相对权重 |
|---:|---:|
| 0 | 0.14210 |
| 0.01 | 0.44735 |
| 0.10 | 0.77479 |
| 0.25 | 0.93065 |
| 0.50 | 1.00000 |
| 0.75 | 0.93065 |
| 0.90 | 0.77479 |
| 0.99 | 0.44735 |
| 1.00 | 0.14210 |

在这个默认设置下，单个 $p=0.5$ 配置的权重约为单个 $p=0$ 配置的 7.04 倍，并非相差几千倍。

配置数量也影响总采样质量。例如，假设有 100 个 $p=0.5$ 配置和 9,900 个 $p=0$ 配置，前者得到的总概率约为 6.64%。因此，“偏好能力边界”不意味着大部分 episode 必然都来自边界配置；配置库的组成仍然很重要。

### 4.5 数值稳定的实现

可以在 log 空间计算：

$$
a_i=
\kappa p^\star\log(p_i+\varepsilon)
+\kappa(1-p^\star)\log(1-p_i+\varepsilon),
$$

$$
\ell_i=
\operatorname{logaddexp}
\left(\max(a_i,\log\varepsilon),\log\varepsilon\right).
$$

然后计算 $\operatorname{softmax}(\ell/T_{\mathrm{eff}})$。这个写法同时保留了附录中的权重下限和取 log 前的加 $\varepsilon$。

常见错误包括：对 $w$ 直接做 softmax、遗漏温度、把 $p$ 当 logits、禁止采样 $p=0$ 的配置，以及用没有放回的抽样替代独立类别采样。

### 4.6 全配置采样与分家族采样

原文的采样作用于所有配置，配置库初始大体均衡，不表示训练时必须始终让三类 reset 各占三分之一。

若为了实现方便先抽家族 $f$、再抽家族内配置，只有下面的方式与全局 SGS 等价：

$$
Q_f=\sum_{i\in f}q_i,\qquad
P(i\mid f)=q_i/Q_f.
$$

固定每个家族 $1/3$、再在家族内部做 SGS，是一种加入了家族配额的变体，应单独标注和比较。

## 5. 与 PPO、奖励和网络的连接

### 5.1 PPO 接口

SGS 改变 reset 配置分布。策略仍然用当前行为策略采集新数据，正常计算 GAE、策略概率比、价值损失和熵项。

**【推导】** 在给定一轮采样分布 $q$ 时，可以把对应训练目标理解为：

$$
J_q(\theta)=\sum_i q_i J_i(\theta).
$$

SGS 不通过梯度优化 $q$，也不对采样器反向传播。正常移植时，不需要给每条 PPO transition 再乘一个 $q_i$；抽样本身已经改变了该配置出现的频率，再乘一次会重复加权。

这不代表它严格优化了原来固定均匀分布上的同一个目标。若研究要求对某个固定目标分布做无偏估计，需要另外研究分布校正；原文 SGS 没有把它作为核心机制。

原始 PPO 的 rollout 数据不能被历史 episode 轨迹替换。SGS 所保存的成功率窗口只是成败统计，不是训练策略用的经验回放池。

### 5.2 本仓库教师基线

入口为 [train_multistate_DQ_teacher.py](../DQ_high-level/train_multistate_DQ_teacher.py)，当前默认读取 [DQ_teacher.yaml](../DQ_high-level/data/cfg/DQ_teacher.yaml)。基准命令从 `DQ_high-level` 目录执行：

~~~bash
python train_multistate_DQ_teacher.py \
  --rl_device cuda:0 --sim_device cuda:0 --timesteps 120000 \
  --task B1Z1PickMulti --object_name sugar_box \
  --experiment_dir DQ_teacher/b1-pick-sugar-box-no-velocity \
  --roboinfo --observe_gait_commands --small_value_set_zero \
  --rand_control --no_velocity_obs \
  --headless --wandb --wandb_name no_velocity_obs
~~~

| 项目 | 当前设置与初版处理 |
|---|---|
| 任务 | 平地、Level02、2 m 起步、最多 100 个高层步；辅助初态沿用同一最终成功标准 |
| 并行与 PPO | 5000 环境，rollout=24，5 epochs、6 minibatches；初版保持 |
| 输入和输出 | 此命令下教师输入 1271 维、动作 9 维；Actor/Critic 读取同一观测，配置 ID 不作为新增输入 |
| 速度观测 | `no_velocity_obs` 删除机器人线速度 3 维和相对物体平面速度 2 维，仍保留关节速度 |
| 控制与网络 | 现有高层策略、候选抓取处理、预训练低层控制器保持；SGS 不补足缺失的时序信息 |
| 奖励 | 现有接近、抬升、保持成功与正则项保持，先隔离采样器的作用 |

每个 rollout 有 120000 条 transition；命令中的 `--timesteps 120000` 表示高层并行交互步数，约对应 5000 次 PPO 更新，不能误解成总共只收集 120000 条样本。

当前 `train_reward_strict=args.timesteps/2`。短试验若提前停止，仍保留原总计划参数，避免改变奖励启用时序。入口目前硬编码 `set_seed(43)`；需要多个训练种子时，先将其接到解析后的 `args.seed`，不能仅改命令行就认为种子已生效。

### 5.3 原文装配奖励

原文成功判据由姿态、横向位置、插入深度等几何条件构成，细节依任务而定。其装配奖励为：

$$
r_t=
100\,\mathbf 1[S(s_t)]
-1\,\mathbf 1[F(s_t)]
-10^{-5}C(\|a_t\|_2^2)
-10^{-4}C(\|a_t-a_{t-1}\|_2^2)
-10^{-4}C(\|\dot q_{t,\mathrm{arm}}\|_2^2),
$$

$$
C(x)=\min(x,10^4).
$$

$F$ 指异常关节速度或物体离开配置的工作空间边界引发的终止；异常速度阈值使用配置关节速度限制的两倍。原文没有把每一种“本 episode 未成功”都定义为这个安全惩罚事件。【原文，附录 A.3.2】

**【迁移设计】** 两种实验目标要分开：

- 验证 SGS 采样能否改善已有任务：先保留已有 reward，在相同 reward 下比较 uniform 与 SGS。
- 验证原文稀疏任务信号的训练思路：再单独使用最终成功奖励与较小的控制正则，并检验配置库是否足以支持学习。

不能只因为引入了 SGS，就宣称可以立即删除所有任务相关设计。成功判据、重置几何和有效控制接口仍然需要任务知识。原文系数也不能不考虑动作单位和控制频率而直接套到其他机器人。

### 5.4 任务时限、失败判据与课程变化

配置成功率依赖允许的执行时长。若一个配置在 5 秒内的成功率为 0，在 20 秒内可能不是 0；这两者不能混在同一套未加说明的统计中。

原文主装配实验使用从零重力开始的课程，在当前阶段成功率超过 80% 后增加重力；另报告过一个不使用该课程的 Franka 训练种子，其结果接近带课程的设置。这只能说明该特定设置下不一定依赖重力课程，不能推广为所有装配任务都可以删除课程。【原文，附录 B.4】

**【未披露】** 本文提供的论文未完整规定课程每次增加多少、该阈值使用的统计窗口，以及课程切换时 SGS 历史如何处理。

**【迁移设计，本仓库】** 初版保留当前物理随机化、台面运动、奖励时序、100 步回合时限和 15 步保持要求；“固定实验条件”不等于关闭原有扰动。Uniform 与 SGS 使用相同设置。后续若改变这些条件，应记录版本或阶段，并明确如何处理旧历史。

## 6. 训练系统的最小接口

以下四项是逻辑职责，不要求在本仓库新增四个独立类。名称是**建议接口，不是作者源代码中的类名**；尤其复用已有 SKRL PPO 和环境中的回合状态。

| 逻辑职责 | 本仓库落点 | 主要输出/职责 |
|---|---|---|
| `ConfigurationBank` | `utils/sgs.py`，按 ID 读取固定 bank | 初态及台面运动参数 |
| `SGSSampler` | 同一新增模块，读取旧 ID 和 `episode_success` | 成功率、采样概率、新配置编号 |
| `EpisodeTracker` | 环境已有回合状态，加 `active_config_id` 和完成/取消标记 | 不重复、归因正确的完成事件，无须单独建类 |
| `PPOTrainer` | 现有 `SequentialTrainer` 与 `PPO` | 继续采集 transition 并执行既有更新 |

采样器最小接口可写为：

```text
observe(config_ids, successes)
    按给定顺序把一批有效 episode 结果写入各自历史

probabilities()
    返回当前所有配置的 SGS 类别概率

sample(num_resets)
    独立、有放回地抽取 num_resets 个配置编号

state_dict() / load_state_dict(...)
    正式工程版本保存和恢复历史、参数、随机数状态
```

一次完成事件应至少包含：

```text
environment_id
episode_serial
configuration_id_at_episode_start
episode_success
termination_reason
completion_step_or_event_sequence
```

`configuration_id_at_episode_start` 必须在覆盖环境当前配置之前取得。很多错误来自先 reset，再拿“当前配置编号”登记刚结束的任务，结果把 A 配置的成败写到了 B 配置。

### 6.1 同一配置的多个并发结果

一个配置可以被多个环境同时抽中，这些结果都有效。必须逐个或按正确的批量算法写入窗口。

不能依赖如下操作自动正确处理重复下标：

```text
success_sum[config_ids] += successes
```

若 `config_ids` 存在重复，普通高级索引更新可能丢失累加；即使累加正确，环形槽位和过期记录的顺序也仍需要处理。

**【迁移设计】** 参考版本先按完成步数和环境编号形成确定顺序，再串行处理结果；正式 GPU 版本可按配置分组，对每组实现有序写入。论文未规定同一个仿真步内的并发结果如何排序。

本仓库的 CPU 顺序版本用于验证结果；5000 环境训练应批量更新 GPU 张量。若同一配置本批超过 H 个结果，只保留最后 H 个，但访问数和环形指针须按全部事件推进。

需区分：

- 多个不同 episode 使用同一配置：全部保留；
- 同一个 episode 被上报两次：第二次应由 `EpisodeTracker` 去重。

### 6.2 本仓库的 reset 入口与事件归因

当前不是在 `step()` 内自动重置。实际顺序见 [SKRL Trainer](../third_party/skrl/skrl/trainers/torch/base.py)：

~~~text
env.step
  → check_termination
  → compute_reward（更新 episode_success）
  → compute_observations
agent.record_transition
agent.post_interaction（可能执行 PPO 更新及现有自动保存）
env.reset
  → B1Z1PickMulti._reset_envs
  → B1Z1Base._reset_envs（累计日志结算，随后清状态）
~~~

把 SGS 结果提交放在 `B1Z1PickMulti._reset_envs` 调用 `super()` 之前：读取旧 `active_config_id` 与 `episode_success`，更新历史，再为这些环境选新 ID。父类继续负责累计成功日志，sampler 不再增加一次 `success_counter`。

首次 `active_config_id=-1` 且 `episode_counter=-1`，只采样初态，不记录结果。正常 `reset()` 只处理 `reset_buf` 标出的环境；直接 `reset_idx()` 却可能主动重启未完成回合。因此有效旧 ID 和非负回合计数只说明已经开始过，不能单独证明自然完成。初版需明确完成/取消标记：真实 step 后结束或超时才提交，人工取消不记失败；如支持主动取消，累计日志也应采用同一约定。

终止 transition 已在 reset 之前交给 PPO，不能再拿新初态观测替换它。SGS 的提交只在此环境钩子发生，Trainer 不再重复提交，也不额外调用第二次 reset。

### 6.3 新配置的应用位置

现有 reset 会随机桌高、机器人朝向、夹爪和运动参数。为避免新配置被覆盖，采用以下顺序：

~~~text
B1Z1PickMulti._reset_actors(env_ids)
  → _reset_table
  → _reset_objs
  → super()._reset_actors
  → 应用选中的 bank 配置（新增）
  → 后续 _reset_env_tensors 中 indexed 上传物理状态
~~~

应用配置时同步设置 `table_commands[env_ids, 4] = bank_table_top_height - table_dimz / 2`、台面 root 高度、`table_heights`、物体高度和机器人相对位置。若遗漏控制命令中的高度，下一步台面控制会覆盖 bank 设置。临近抓取与已到达抓取位姿需设置机械臂/夹爪关节及相容控制目标。三类物体初始位于原桌面支撑高度，恢复时以 bank 实际快照为准；`init_height` 保留名义值。

完成物理状态和控制目标初始化、刷新 `arm_base/base_obj_dis` 等派生状态，最后生成首帧观测。机械臂目标应匹配保存姿态，不能随后被默认目标覆盖。高层缓存和低层历史采用一致的重置规则，Uniform 与 SGS 共用此路径。

第三类的 `gripper_dof_pos` 恢复库中随机目标；恢复后仍由教师动作正常控制夹爪。`curr_height`、`highest_object` 按新初态真实高度初始化，成功计数清零。不把“到达位姿”或“夹爪闭合”当作成功。

不要为某个重置环境额外反复推进全局仿真，影响其他活动环境；root/DOF 状态按 GPU 批量提交契约上传。初态几何与碰撞检查在离线构库环境完成，训练从缓冲区直接取样。

## 7. 本仓库训练循环

下面是适配后的伪代码，用于说明已接入的 bank/sampler 调用顺序。沿用现有 SKRL 的逐步交互循环，不另写一套 PPO 更新。

~~~text
创建固定 bank 和空历史 sampler
    mode = uniform 或 sgs
    p_init = 0.0，初始概率均匀
创建环境，active_config_id 初始化为 -1
沿用现有 Policy、Value、PPO、RandomMemory、SequentialTrainer

states = env.reset()
    首次 reset 只采初始配置，不提交结果
    应用物理状态、控制目标，清回合状态，生成一致观测

对每个高层 timestep：
    agent.pre_interaction(...)
    actions = agent.act(states)
    next_states, rewards, terminated, truncated, infos = env.step(actions)
    agent.record_transition(...)
        保存本步真实 next_states 和结束信息

    agent.post_interaction(...)
        现有 PPO 每累计 24 步在这里更新
        不在外层再调用一次 GAE 或 PPO update

    如果有环境结束：
        states = env.reset()
            在 B1Z1PickMulti._reset_envs 的新增钩子中：
                提取真正完成回合的旧 active_config_id 和 episode_success
                sampler.observe(...)，每个完成事件一次
                sampler.sample(num_resets)，采新配置
                更新 active_config_id
            父类按原逻辑结算累计日志
            应用 bank 初态，清回合缓存，生成首帧观测
    否则：
        states = next_states

    按需记录 sampler 诊断
~~~

三个顺序约束：

- 成败统计与 reset 发生在 episode 边界；rollout 满 24 步不等于所有环境结束。
- 一个 episode 执行期间不换配置 ID；即使 episode 跨越 PPO 更新，结果仍归其起始配置。
- 一个配置历史包含近期行为策略的执行结果，不需要每次更新策略就清空历史。

初版从头训练，现有模型 checkpoint 可用于评估，但不是完整 SGS 恢复点。若以后支持续训，需将模型/优化器/归一化与 scheduler 状态、bank 标识、sampler 历史/RNG、全局进度同步保存。当前自动保存位于本步 reset 之前，保存间隔 5000 也不是 rollout 24 的倍数；完整快照应在更新边界且 reset 结算后生成。恢复时保持原总训练计划和奖励时序，重新开始仿真回合，中断回合不补记失败。

| [训练入口](../DQ_high-level/train_multistate_DQ_teacher.py)、[配置文件](../DQ_high-level/data/cfg/DQ_teacher.yaml) | 加载 bank、选择采样模式和参数；不改 PPO 数学实现 |

教师 YAML 的 `env.sgs` 包含 `mode`（disabled/uniform/sgs）、`bank_path`、`history_size=100`、`target_success=0.5`、`kappa=1`、`temperature=2`、`epsilon=1e-4`、`p_init=0.0`。bank 本身保存 1536 条初态、三类标签及版本，运行时校验实际数量。

当前入口默认读 `data/cfg/DQ_teacher.yaml`，通过 `--sgs_mode`、`--sgs_bank` 选择采样方式和库；构库的独立 `--reset-config` 只供离线入口读取。禁用 SGS 时沿用原 reset；启用时只在同一 bank 上切换 uniform/sgs。

### 8.2 只做一组必要训练对照

| 实验 | 配置库 | 采样 |
|---|---|---|
| Uniform | 同一份 1536 条三类配置 | 所有配置等概率 |
| SGS | 同一份 1536 条三类配置 | 本文完整 Beta 权重与温度公式 |

两组共用初态应用代码、奖励、PPO 参数、观测、低层控制器、随机化和训练预算。先用同一个实际生效的种子完成探索性对照；发现改善后再增加训练种子确认，不把单次差异视为稳定收益。

主指标是**独立的原始 2 m、Level02 分布上的保持成功率**。两组使用同一份从原始分布另采的测试配置，不能从训练 bank 复制。比较相同训练步数的模型，使用独立评估环境、固定案例数并完整统计；冻结 scaler，不训练、不更新 SGS。

原 `get_trainer(is_eval=True)` 同时设置确定性 Actor 和环境的抬起即成功分支。独立评估入口已将两者分开：明确 `policy.deterministic=True`，但成功仍要求 `pick_counter >= hold_steps=15`，允许抬起后继续执行。普通 `policy.eval()` 本身不保证确定性动作。现有 `best_agent.pt` 按训练回报选择，不用于替代相同步数的主对照。

附加诊断只需：各类初态的训练成功率、实际抽样比例、每配置的近期成功率与访问数。它们用于解释 SGS 如何分配训练机会，不能代替完整任务评估。若 SGS 与 Uniform 相近，应如实报告采样器没有显示额外收益；若全部配置持续失败，先调整初态覆盖，不额外加强采样集中度。

### 8.3 实现后的最小检查

- 采样器：相同成功率得到均匀分布，两端概率非零；空历史按 `p_init=0.0` 处理，未填满历史不补失败；重复 ID 和超过 H 个并发结果不丢失。
- 回合归因：首次 reset 不记结果；成功、失败、超时归旧 ID；主动取消不伪造失败；每回合一次。
- 初态应用：配置不会被父类覆盖；物体支撑、机械臂姿态和控制目标一致，reset 后没有异常穿透、回拉或立即终止。
- 已到达抓取位姿：末端对齐候选，随机开度及目标从缓冲区正确恢复，物体未预抬升；不要求已经抓稳，`pick_counter` 和成功标记为零。三类足底在近地几何范围内，不增加稳定站立验收。
- 评估：在首次抬起时不会提前结束，确实执行 15 步保持要求。

先完成这些检查，再比较训练效果。整个初版保留论文的固定配置、近期成功率、全局平滑采样和正常 PPO 更新；三类初态从训练开始同时可访问，学习顺序由策略表现自然决定。
