## 1. 一页结论

| # | 方向 | 针对的代码现象 | 改动量 | 新颖度 | 建议顺序 |
|---|---|---|---|---|---|
| 0 | **先修：时限截断的处理** | 超时被当成真终止，观测里没有时间 | 很小 | — | 最先（影响所有对照） |
| 1 | **时空抓取 token：把 GFM 改成“拦截式”抓取选择** | 30 个候选只按**当前**物体位姿变换，未来位姿只进 Query；输出是软平均 | 中 | **高** | 核心 |

**如果要讲成一个论文故事**，最初的建议是 **1 + 3**：
“动态抓取的难点在于**在哪里、什么时候**相遇” → 方向 1 让策略在“候选抓取 × 未来时刻”上做选择；方向 3 让课程自动生成“刚好在拦截失败处”的初态。两者都直接围绕“动态”展开，不是通用的 RL 技巧，也正好接在你已有的 EKF 和 SGS 后面。

在此基础上，方向 8–10 补上了另外两个问题：**预测有多可信**、**底座和手臂各负责什么**。四个问题合起来就是一条完整的主线，见第 14 节。方向 2、5、6 是低成本的增益项，适合作为消融里的 “+tricks”。

## 2. 先修项：时限截断的处理（方向 0）

**代码事实。**
- Wrapper 把 `truncated` 恒置为 0（[`wrapper.py:137`](../DQ_high-level/utils/wrapper.py#L137)），`terminated` 是包含超时在内的 `reset_buf`；环境虽然写了 `extras["time_outs"]`，但没有传给 PPO。
- skrl PPO 的 `time_limit_bootstrap` 默认 `False`，训练入口也没打开（[`ppo.py:276`](../third_party/skrl/skrl/agents/torch/ppo/ppo.py#L276)）。
- 默认脚本没开 TSIL，所以观测里**没有任何时间信息**。

**后果。** 第 100 步超时被当作真终止（后续价值为 0），但网络看不到“还剩多少步”。同一状态有时后面还有 90 步、有时马上被截断，价值目标因此含混。Pardo 等人（ICML 2018）把这称为状态混叠，会导致不稳定和次优策略。

**两种修法（二选一）。**
1. **只给 critic 加时间特征**（推荐）：`Value` 额外输入 `progress_buf / max_episode_length`，Actor 不变。保留“100 步内完成”的任务语义。
2. 截断自举：把 `timeout_buf` 作为 `truncated` 传出，并打开 `time_limit_bootstrap`。注意这会让价值函数把超时当成“还能继续”，减弱时间压力；TSIL 打开时尤其要想清楚两者的关系。

这不是创新点，但它影响后面每一组对照，建议最先改。

**实现状态（2026-11-14）：已按修法 1 实现。**
- 开关：`--critic_time_obs` / `--no_critic_time_obs`（后出现者生效），对应 YAML `env.criticTimeObs`（仓库默认 `False`，保存在实验配置中，评估时自动恢复）。[`train_teacher_sgs_ekf.sh`](../DQ_high-level/train_teacher_sgs_ekf.sh) 默认打开，TSIL 与 727 启动脚本继承；`train_teacher_ekf.sh` 未改。
- 观测：在机器人状态之后、EKF 预测块之前插入 1 维 `progress / maxEpisodeLength`（reset 后为 0，超时步为 1）。EKF、TSIL 时间通道、候选抓取和上一动作的位置都从末尾计数，因此保持不变。
- 网络：`Policy` 在 MLP 输入中剔除这一维，参数形状与不开开关时完全相同；`Value` 使用全部输入。GFM 的 Query 不受影响。
- 没有选修法 2 的原因：本仓库的 skrl PPO 计算 GAE 时只看 `terminated`，截断自举也用 `V(s_t)` 近似 `V(s_{t+1})`。如果把超时改成 `truncated`，GAE 会跨过回合边界接上下一回合的价值，结果反而错误。
- 未适配学生端（`_compute_states_buf`、`restore_student_teacher_observation_config`）；带该通道的教师 checkpoint 暂不能直接用于蒸馏。
- 测试：[`tests/test_critic_time_obs.py`](../DQ_high-level/tests/test_critic_time_obs.py)（CPU，无需 Isaac Gym）。尚未在 GPU 上跑真实训练。

## 3. 方向 1：时空抓取 token —— 把 GFM 改成“拦截式”抓取选择

### 3.1 代码现象

- 30 个候选抓取由**当前**物体世界位姿变换得到（[`b1z1_pickmulti.py:812`](../DQ_high-level/envs/b1z1_pickmulti.py#L812)），再转到臂基坐标系 A。
- EKF 的 0.6 s / 0.9 s 预测位姿只拼进 **Query**（[`predictattention.py:37`](../DQ_high-level/modules/predictattention.py#L37)）。Key / Value 仍然是“当前时刻”的候选，所以网络必须**隐式**学会“把抓取点平移到物体将要到达的位置”。
- 输出是 softmax 加权平均后再线性投影成 6 维（[`predictattention.py:48-50`](../DQ_high-level/modules/predictattention.py#L48)），它不是在“选”一个抓取。两个朝向相反的候选平均后可能得到一个无效姿态；RPY 在 ±π 附近不连续，也让加权平均更不可靠。
- 候选的选择在相邻两步之间没有任何一致性约束，动态场景下可能来回切换。

### 3.2 做法

**(a) 时空 token。** 用已有的 EKF 输出，把每个候选抓取变换到每个预测时刻的物体位姿上：

```text
token(i, h) = T_A(t) · T_obj(t+h) · T_grasp_i      i ∈ 30 个候选, h ∈ {0, 0.6, 0.9}
→ 30 × 3 = 90 个 token
```

最近一次提交已经把两者统一在臂基坐标系 A（EKF 在 A 系预测、候选抓取也在 A 系），所以变换可以直接复用。每个 token 的特征：

| 特征 | 维度 | 说明 |
|---|---|---|
| 位置 | 3 | A 系 |
| 旋转 | 6 | 用 6D 旋转表示替代 RPY，避免不连续（Zhou et al. 2019） |
| 时刻 `h` 及 EKF valid | 2 | 让注意力区分“现在能抓”和“等它过来再抓” |
| 简单可达性 | 2–3 | 到臂基距离、接近方向与底座朝向夹角，是 Akinola 2021 可达性筛选的廉价版 |

**(b) 选择而不是平均。** 两条路线：
- 保留软注意力，但输出**注意力后的 d_model 维嵌入**（不再压成 6 维），并额外输出概率最大 token 的位姿（直通估计 straight-through）；
- 或者用 Gumbel-softmax 做可微硬选择，温度随训练退火。

**(c) 选择的时间一致性。** 给每个 token 加一个“上一步是否被选中”的标记位，让网络自己学会保持；或者对相邻两步的注意力分布加一个小的 KL 惩罚。GAP-RL 的 Graspable Region Explorer 也在解决这个“抓取点前后不一致”的问题。

**(d) 可选：只依赖状态的拦截塑形。** `Φ(s) = −min_{i,h} ‖p_EE − p_token(i,h)‖`，用 `γΦ(s')−Φ(s)` 做势函数塑形。Φ 只依赖状态，因此不改变最优策略。注意：如果改成“到网络所选 token 的距离”，Φ 就依赖网络输出，不再是严格的势函数。DynaMOMA 用的“预期引导奖励”是同一类思路。

**(e) 可选：接触时的速度匹配。** 末端靠近物体（例如距离 < 0.1 m）时，加一项 `−‖v_EE − v_obj‖`，鼓励末端在接触前跟上物体的速度，减小冲击。抓取运动物体的工作里这是常见做法（IMA-Catcher 规划接触前速度差最小的末端轨迹；Impact-Friendly Catching 研究非零速度下的接取），所以只把它当作方向 1 中“怎么相遇”的组成部分，不单独宣称创新。它不是势函数形式，会改变最优策略，权重要小。

### 3.3 为什么新颖

已有的动态抓取工作要么是固定臂 + 规划（Akinola 2021），要么把抓取点作为观测输入 RL（GAMMA、GAP-RL），DynaMOMA（2026）用扩散模型预测短时域抓取轨迹再喂给 RL。**把“候选抓取 × 未来时刻”做成同一组注意力 token，让 RL 策略自己决定在哪个抓取、哪个时刻拦截**，在腿式移动操作上还没看到。它也直接回答了 DQ-Net 的核心问题：动态物体应该选哪个抓取点。

### 3.4 风险与代价

- token 数从 30 变成 90，计算量很小；但 Policy / Value 都要改 `PredictAttentionSelector`，旧 checkpoint 不兼容。
- EKF 外推在抓住之后失效（物体跟着夹爪走）。可以在 `lifted_object` 或夹爪闭合后，把 `h>0` 的 token 屏蔽掉。
- 如果学生网络也用 GFM，学生端要用自己的位姿估计构造同样的 token。

### 3.5 最小实验

| 组 | 内容 | 要回答的问题 |
|---|---|---|
| G0 | 当前 GFM | 基线 |
| G1 | 只把 RPY 换成 6D，输出改为 d_model 嵌入 | 表示方式本身的影响 |
| G2 | G1 + 时空 token | **主假设**：显式的未来候选是否更好 |
| G3 | G2 + 选择一致性 | 是否减少抓取点切换、提高保持成功率 |
| G4 | G3 + 拦截势函数塑形 | 塑形是否加快早期学习 |

建议额外记录两条诊断曲线：注意力熵、相邻两步 argmax token 的切换率。

## 4. 方向 2：左右镜像对称

### 4.1 代码现象

- Level02 台面横向速度的**正负号随机**（[`b1z1_base.py:1055`](../DQ_high-level/envs/b1z1_base.py#L1055)），绕 z 轴转速在 ±0.3 rad/s 之间对称采样；机器人与物体初始 yaw 都在 ±15° 内对称随机。
- 机械臂安装在底座中线上（臂基偏移 `[0.3, 0, 0.09]`），B1 + Z1 左右对称。
- 因此“物体从左边来”和“从右边来”是镜像关系，但 PPO 必须分别学会，两侧的成功率也可能不一样。

### 4.2 镜像映射（关于机器人 x-z 平面）

| 量 | 映射 |
|---|---|
| 位置 / 速度 | y → −y |
| 姿态 RPY | roll → −roll，pitch 不变，yaw → −yaw |
| 动作 | Δy、Δroll、Δyaw、yaw 角速度指令取反；Δx、Δz、Δpitch、vx、夹爪不变 |
| Z1 关节（已核对 URDF 轴） | `waist`(z)、`forearm_roll`(z)、`wrist_rotate`(x) 取反；`shoulder`/`elbow`/`wrist_angle`/夹爪 (y) 不变 |
| 腿 | 左右互换；`hip`(x) 取反，`thigh`/`calf` 不变 |
| 30 个候选抓取 | 逐个镜像（`R → M R M`，`M=diag(1,−1,1)`）。GFM 对候选顺序不敏感，所以不需要重新配对 |
| 物体点云特征（1024 维） | sugar_box 近似镜像对称，可不变；多物体时只对对称物体启用 |

### 4.3 做法（按风险从低到高）

1. **镜像损失**：在 PPO loss 上加 `‖μ(M_s s) − M_a μ(s)‖²` 和 `‖V(M_s s) − V(s)‖²`。不改采样，最安全。
2. **数据增强**：每个 mini-batch 加入镜像样本，沿用原样本的优势值。Mittal 等（ICRA 2024）给出了 on-policy 下使用增强样本的理论依据，并报告增强比镜像损失回报更高、更稳定（这一点来自二手综述，未逐页核对）。

### 4.4 风险

- 冻结的底层控制器不一定严格对称；镜像样本是“反事实”数据，底层越不对称，偏差越大。可以先跑一组镜像评估：把评估场景整体镜像，比较两侧成功率，作为底层对称性的检验。
- 观测布局里每一段都要映射正确，建议写单元测试：`M(M(s)) = s`，以及对称初态下环境前若干步观测确实互为镜像。

**新颖度**：对称增强在四足步态上常见，用在**动态抓取 + 腿臂协同**、且同时镜像候选抓取集合的做法少见。

## 5. 方向 3：SGS 配置库在线演化

### 5.1 代码现象

- v12 配置库 1536 个配置（3 类 × 512），构建后带指纹、不可变；SGS 只按近期成功率重新分配采样权重。你自己的 SGS 方案文档也写了：“SGS 自身不会生成新的可解状态”。
- `pregrasp` / `near_goal` 是离线按几何规则构造的，未必等于策略真正会走到的状态；策略在 full_task 中失败的位置，也不一定被配置库覆盖。

### 5.2 做法

**(a) 自生成初态（主方案）。** full_task 回合进行中，在随机步对一部分环境拍快照，保存的字段与 SGS 恢复配置时写回的字段完全相同（`_reset_sgs_envs` 里的根状态、DOF、末端目标、夹爪目标、台面参数、刚体状态、Jacobian 等）。回合**失败**后，把它的快照写入一个新的 “self_play” 类（例如 512 个槽的环形缓冲），历史清空，由 SGS 照常采样。

- 这些状态是策略自己走到的，因此物理上一定可达；初态分布也贴近策略真实的状态分布。
- 它们恰好位于“失败之前”，和反向课程（Florensa 2017）、Go-Explore 的“回到有希望的状态再探索”是同一个思想。
- 构库时的接触检查仍需保留一部分：例如快照时物体处于被推挤的接触中，可以先丢弃。

**(b) 变异已有配置（ACCEL 式）。** 定期取成功率处于中间段的“前沿”配置，对参数做小扰动（台面速度略增、底座更远、朝向更偏），用现有的 `sgs_bank_builder` 在小批量上做物理验证，替换掉已经掌握（历史满、成功率 > 0.95）或长期为 0 的配置。ACCEL 用“对前沿关卡做小编辑”持续生成难度刚好的关卡。

**(c) 评分。** SFL（NeurIPS 2024）发现常用的“遗憾近似”其实跟踪的是成功率，并提出用可学习性 `p(1−p)` 选关卡。你的 SGS 核 `p^0.5(1−p)^0.5` 已经是同一类评分，所以可以直接沿用；SFL 的另一启示是**定期刷新缓冲区**，而不是只在固定池里重新加权。

### 5.3 为什么新颖

SGS 原文和你的实现都只在固定池上重新加权。“**SGS 采样 + 从策略自身失败轨迹生成初态 + 变异前沿配置**”把初态采样从“分配练习次数”扩展到“生成练习内容”，并且针对动态拦截任务。

### 5.4 风险与工程注意

- 配置库目前按指纹做严格校验，TSIL 的目标也按 `config_id` 存；动态槽位需要独立的 ID 区间，替换时清空 SGS 历史和对应的 TSIL 目标。
- 主指标仍只统计 full_task 类（`_record_episode_outcomes` 已经这样做），新类别不会污染主结果。
- 风险是课程漂移：缓冲区可能被大量“几乎必败”的状态占满。可以限制 self_play 类的总采样比例，或者用你文档里已经提出的均匀混合（建议 D）兜底。

## 6. 方向 4：分块并行策略梯度（SAPG / EPO）

### 6.1 代码现象与前置诊断

8192–16384 个环境、24 步 rollout、单一高斯策略。SAPG（ICML 2024 oral）报告：PPO 在环境数超过某个点后不再受益，性能饱和。

**先做诊断再决定是否投入**：固定迭代次数，比较 4096 / 8192 / 16384 个环境的 full_task 成功率曲线。如果 8192 和 16384 几乎重合，说明已经饱和，这个方向才值得做。

### 6.2 做法

- 把环境分成 M 块（例如 6 块），共享主干网络，每块有一个可学习的块嵌入。
- leader 块用自己的数据加上 follower 块的数据更新，follower 数据通过重要性比 `π_leader / π_follower` 修正，仍然使用 PPO 的裁剪目标；follower 只用自己的数据更新。
- **本任务特有的改动**：每块使用**不同参数的 SGS 采样器**（不同的目标成功率或温度，或者偏向不同初态类别）。这样多样性同时来自行为和初态分布，leader 能吸收更多样的成功轨迹。
- EPO（2025）在 SAPG 之上加了种群选择（淘汰差的块、复制好的块），可以作为第二步。

### 6.3 代价

需要替换 skrl PPO（你已经有 `TSILPPO` 自定义 agent 的经验）；和 TSIL 同时开启时，经验回放与重要性采样的交互需要单独验证。

## 7. 方向 5：约束即终止（CaT）

### 7.1 代码现象

- 硬终止：roll/pitch > 0.8、躯干高度 < 0.1、末端 z 跟踪误差 > 0.2 m（`ik_fail`，[`b1z1_base.py:1628`](../DQ_high-level/envs/b1z1_base.py#L1628)）、yaw 偏离 > 70°（[`b1z1_pickmulti.py:977`](../DQ_high-level/envs/b1z1_pickmulti.py#L977)）、物体掉落。
- yaw 在 60°–70° 之间另有 `limit_yaw_rotation_penalty`，权重 0.4。
- `command_reward`（靠近物体时鼓励底座减速）在 `global_step < total_timesteps/2` 时恒为 0（[`reward_vec_task.py:67`](../DQ_high-level/envs/reward_vec_task.py#L67)），也就是在第 60000 步**突然**加入奖励，价值函数的目标在这一刻跳变。

### 7.2 做法

CaT（IROS 2024）把约束 `c_k(s,a) ≤ 0` 变成随机终止：

```text
P(终止) = max_k  p_max,k · clip(c_k⁺ / c_max,k, 0, 1)
```

- 软约束：yaw 偏离（替代“惩罚 + 70° 硬终止”的组合）、末端跟踪误差、**靠近物体时的底座速度**（替代 T/2 奖励开关）。
- `p_max` 从 0 逐渐升到目标值，用平滑课程替代奖励开关。
- 真正的失败（摔倒、物体掉落）仍保持硬终止。

**好处**：去掉一个权重和一个阶跃式课程；终止的“代价”自动等于失去的未来回报，与奖励尺度一致。代价是需要调 `p_max` 和 `c_max`，以及 CaT 终止会被 SGS 记为失败，这是合理的，但会改变各类配置的成功率统计口径。

## 8. 方向 6：时间相关的探索噪声

### 8.1 代码现象

- `log_std_parameter` 与状态无关，每步独立采样（[`train_multistate_DQ_teacher.py:153`](../DQ_high-level/train_multistate_DQ_teacher.py#L153)）。
- 末端位置/姿态动作是**增量**，会累积到末端目标里，白噪声让目标做随机游走。
- 底座指令开了 `smallValueSetZero`（[`b1z1_base.py:2141`](../DQ_high-level/envs/b1z1_base.py#L2141)）：小于阈值的指令会被置零，白噪声会让底座在“走 / 停”之间频繁切换。

### 8.2 做法

Hollenstein 等（AAAI 2024）在 PPO 中保持高斯边缘分布不变，只把采样噪声换成有色噪声（每个环境一条序列，回合开始时重置）。他们发现 PPO 最适合介于白噪声和粉红噪声之间的颜色，推荐 β = 0.5，**而且并行环境越多，越适合相关性更强的噪声**，这一点正好符合本仓库的设置。改动只在策略的采样处，log-prob 的计算公式不变。

## 9. 方向 7（简述）：阶段化多头 critic

稀疏的 `pick_up: 50` 与密集的接近/抬升塑形共用一个价值头。可以按奖励组拆成多个价值头（接近、抬升、成功、惩罚），分别归一化后加权合成优势；你库里的 GCR-PPO 用的就是多头 critic，再加梯度冲突处理。Multi-critic 末端速度跟踪（2025）和接触引导的非抓取移动操作（2026）都报告了按奖励组拆分 critic 的收益。如果先做了方向 0 和 5，奖励项会少一些，这个方向的必要性也会降低。方向 10 也需要多个价值头，两者可以共用一套实现，区别见 12.3。

## 10. 方向 8：不确定性感知拦截 —— 让策略知道“预测有多可信”

### 10.1 代码现象

- **Level02 的运动正好符合 EKF 的模型。** `compute_table_command_level_02`（[`b1z1_base.py:1811`](../DQ_high-level/envs/b1z1_base.py#L1811)）在整个回合里使用固定的台面局部速度 `vy`，一半回合另加固定的 yaw 角速度；`floating_table_control` 再用台面当前朝向把局部速度转到世界系。所以物体在世界系里做的是恒定 body twist 运动（直线或圆弧），这正是 `RollingSE3Predictor` 的匀速 SE(3) 模型。EKF 在 A 系拟合（[`b1z1_pickmulti.py:780`](../DQ_high-level/envs/b1z1_pickmulti.py#L780)），误差主要来自机器人自身的运动，而不是物体运动的不可预测性。
- **因此“什么时候该相信预测”这个问题在训练中不存在**，预测带来的收益也是在理想条件下测出来的。真实目标会加速、拐弯。
- **变速运动其实已经写好了。** Level03 / Level04（[`b1z1_base.py:1849`](../DQ_high-level/envs/b1z1_base.py#L1849)、[`#L1866`](../DQ_high-level/envs/b1z1_base.py#L1866)）每隔一段时间重新采样 `vx`、`vy`、yaw 角速度（Level04 还有竖直速度），两次切换之间仍是匀速。切换间隔按物理步计，第一次约为 `rand_change_step × 6` 步 ≈ 1.2–1.8 s（物理步长 0.005 s），之后的间隔随切换次数变化。
- **SGS 目前只支持 Level02**（[`b1z1_pickmulti.py:134`](../DQ_high-level/envs/b1z1_pickmulti.py#L134)），但配置里已经存了 `table_vy`、`rotation_enabled`、`table_yaw_rate`，还有一个只在 Level03/04 里起作用的 `table_change_interval`（[`b1z1_pickmulti.py:251`](../DQ_high-level/envs/b1z1_pickmulti.py#L251)）。
- **EKF 协方差算了但没有输出。** `predict()` 里计算 12×12 协方差（[`pose_prediction.py:203`](../DQ_high-level/modules/pose_prediction.py#L203)–223），只用来算增益和做有限性检查（L230）。而且 Q、R 固定（L141–142），每次都从单位阵开始在固定的 5 帧窗口上重新滤波，结果几乎只取决于采样间隔，不取决于数据。即使把它输出，也反映不了“物体刚刚变向”。

### 10.2 做法

**(a) 训练分布加入分段匀速运动。** 复用 Level03/04 的切换逻辑：让一部分回合在 Level02 的速度范围内按间隔切换速度或转向，切换比例和切换后的速度范围作为课程参数，从 0 逐渐升高。SGS 需要放宽 Level02 的限制，并在配置里新增运动字段（例如运动模式、`vx`、切换后速度的随机种子）。这些字段也正好是方向 3 可以变异的维度。

**(b) 不确定性特征：实际发生的预测误差。** 对每个预测时刻 `h`，取 `h` 秒前对“现在”所做的预测，与当前测量比较：

```text
e_h(t) = ‖p̂(t | t−h) − p(t)‖         位置误差（A 系）
ε_h(t) = ∠( R̂(t | t−h)ᵀ · R(t) )      旋转误差
```

- 因果、可计算：只用过去的预测和当前测量。
- 与数据相关：匀速时接近 0；物体变向后变大；EKF 适应新速度后（5 帧窗口约 0.75 s）再回落。这正是策略需要知道的。
- 实现：每个环境一个长度约 7 步的环形缓冲，保存过去的预测及其时间戳。高层步长随 `control_freq_low` 在 7–8 之间随机（约 0.14–0.16 s），`h` 不是步长的整数倍，所以按时间戳取最近的一条或做线性插值。EKF 未就绪时用“未知”标志位代替。
- 可选：再做一个时间常数约 1 s 的指数平滑，减少单步噪声。
- 放进方向 1 的 token：同一个 `h` 的 90/3 = 30 个 token 共享 `(e_h, ε_h)`。`h = 0` 的 token 对应当前测量，误差为 0。

**(c) 可选：只给 critic 的特权信息。** “距离下一次切换还有多久”只给 critic（和方向 0 的做法一样），不给 actor。actor 看到它就不需要学会应对不确定性了。

### 10.3 可以检验的假设

Belousov 等（NeurIPS 2016）在最优控制框架下分析接球问题：最优策略会根据观测噪声与系统噪声之比，在**反应式**（持续跟踪物体当前位置，类似凝视启发式）和**预测式**（提前移到预测的落点）之间切换。对应到本任务：

- **预期：** 预测误差大时，GFM 的注意力从 `h = 0.9` 的 token 移向 `h = 0`；误差小时偏向未来的 token。
- **诊断：** 按 `e_h` 分桶，统计注意力质量在三个 `h` 上的分布，画“注意力–不确定性”曲线。不需要额外训练，就能得到一张很有说服力的分析图。

### 10.4 为什么新颖

- GraspARL 用对抗性的“移动者”生成物体轨迹（思路来自 RARL），但它是固定臂，策略也不接收预测可信度。
- Think Fast 做的是信念空间中的拦截规划，不是 RL 策略。
- 我检索到的动态抓取 RL 工作都把预测当作观测输入，没有显式告诉策略“预测有多可信”，也没有分析策略在反应式和预测式之间的切换。这一判断只基于有限的检索。

### 10.5 最小实验

| 组 | 训练 | 要回答的问题 |
|---|---|---|
| U0 | 方向 1 的 G2（只有 Level02） | 基线 |
| U1 | U0 + 分段匀速训练 | 训练分布本身的影响 |
| U2 | U1 + 实际预测误差特征 | **主假设**：知道预测可信度是否更好 |
| U3 | U1 + EKF 协方差特征（替代 U2 的误差特征） | 实际误差是否比固定 Q/R 的协方差更有用 |

所有组都在 Level02、分段匀速和 **Level03 / Level04**（`vx`、竖直速度不在训练分布里）上测试，后者是分布外泛化的主结果。

### 10.6 风险

- 分段匀速会降低 full_task 成功率，需要按课程逐渐提高切换比例。
- 物体变向后，EKF 需要约一个窗口（5 帧）才能适应。如果误差特征提供的信息不够，可以再加一个短窗口（2–3 帧）的快速预测器，作为另一组 token。

## 11. 方向 9：事后标注的拦截 token 监督

### 11.1 代码现象

- GFM 选哪个抓取，只能通过 PPO 的策略梯度间接学习；主要的任务信号 `pick_up: 50` 很稀疏。
- 抓起的判定 `lifted_grasp_mask`（[`pick_success.py:53`](../DQ_high-level/utils/pick_success.py#L53)）是：物体比静止高度高出阈值、末端到物体距离 < 0.2 m、夹爪指令 < 0。环境不记录“实际执行的是哪一个候选抓取”。

### 11.2 做法

1. **找实际抓取时刻 t\***：回合中第一次同时满足“夹爪指令 < 0、末端到物体距离小于较小的阈值（例如 0.05 m）、物体离开静止高度 1–2 cm”的步。成功回合一定有 t\*；失败回合可能有（抓起后掉落、没保持住），也可能没有。
2. **找实际执行的抓取**：在物体坐标系下比较 t\* 时的末端位姿 `T_obj(t*)⁻¹ · T_EE(t*)` 与 30 个候选，取位置加旋转距离最近的 `i*`。
3. **回标**：对每个 `h ∈ {0.6, 0.9}`，在 `t* − h` 时刻，token `(i*, h)` 恰好代表“在 t\* 用抓取 i\* 拦截”。成功回合把它标为正，抓过但失败的回合标为负。可选：再要求该 token 预测的世界系位置与实际末端位置误差小于阈值，把 EKF 预测错的样本过滤掉。
4. **训练 token 打分头** `s(i, h) = MLP(token 特征, Query)`：
   - 成功样本用 90 选 1 的交叉熵（目标 `(i*, h)`）；失败样本对 `(i*, h)` 用 BCE 负标签。
   - 用法一：作为辅助损失，和 PPO 共享 GFM 的 Key / Query 编码器。
   - 用法二：把 `log σ(s)` 加到注意力 logit 上作为先验，权重随训练退火。

### 11.3 可行性

- 高层一步约 0.14–0.16 s，0.6 / 0.9 s 约为 4 / 6 步。
- 标签有延迟：回合是否成功要等保持 `hold_steps` 步后才知道，常常跨过 24 步的 rollout 边界。所以需要一个按环境的小缓冲：
  - 每步只存重建 token 所需的位姿（物体位姿、EKF 预测、机器人位姿，约 30 维），保存最近约 7 步。30 个候选抓取对每个物体是固定的，token 可以在需要时重新计算，不必存 90 × 特征维。
  - 检测到 t\* 时，取出 `t* − h` 的位姿；等结局确定后，把标好的样本放进一个 FIFO 数据集，在每次 PPO 更新时一起训练。
- 可参考 [`tsil_replay_gpu.py`](../DQ_high-level/utils/tsil_replay_gpu.py) 的 GPU 缓存写法，以及 [`tsil_ppo.py`](../DQ_high-level/utils/tsil_ppo.py) 在 PPO 更新中加入额外损失的写法。

### 11.4 为什么新颖

- QT-Opt 用抓取是否成功给 Q 函数做自监督，但那是静态抓取。
- HER 把“实际达到的状态”重标为目标。
- 这里把“事后实际执行的拦截方案（哪个抓取 × 哪个时刻）”回标到候选 token 上，用来监督动态抓取的选择，相当于把 HER 的思想用到抓取选择上。我没有检索到同样的做法。
- 额外产出：一张随时间变化的“动态抓取可行性热力图”（token 打分随时间的变化），可解释性好，适合放进论文。

### 11.5 风险

- t\* 依赖阈值，夹爪指令只是抓取的代理信号，不是接触力，所以标签有噪声。如果能读到夹爪手指的接触力，用它定义 t\* 更可靠。
- 每个回合最多 2 个标签，而 token 有 90 个，样本稀疏且不平衡；需要按 `h` 平衡采样。
- 依赖方向 1：没有时空 token，就没有回标的对象。

## 12. 方向 10：按拦截阶段混合底座/手臂优势

### 12.1 代码现象

9 维动作：`[0:6]` 末端位姿增量、`[6]` 夹爪、`[7]` 底座 `vx`、`[8]` yaw 指令。按 [`DQ_teacher.yaml`](../DQ_high-level/data/cfg/DQ_teacher.yaml) 中非零的奖励项，大致可以按“主要受哪组动作影响”分组：

| 组 | 奖励项（权重） | 说明 |
|---|---|---|
| 底座 | `base_approaching` 0.01、`command_reward` 0.05、`action_rate` −0.001、`limit_yaw_rotation_penalty` 0.4 | `action_rate` 只看 `actions[7:9]`；`command_reward` 看底座 `vx` 指令 |
| 手臂 | `ee_orn` 0.01、`acc_penalty` −0.001、`lifting` 0.8、`pick_up` 50 | `acc_penalty` 只看臂关节加速度 |
| 混合 | `approaching` 0.5、`grasp_base_height` 0.5 | 末端–物体距离两组都影响；底座高度奖励还乘了保持进度 |

当前只有一个价值头、一份优势，9 维动作共用同一个信号：底座动作也要为抬升是否成功“背锅”，手臂动作也要承担 yaw 惩罚带来的方差。

### 12.2 做法

- **两个价值头**：`V_b` 估计底座组回报，`V_a` 估计手臂组回报。混合项按比例分到两组，或在两组中各放一份。
- **分组的 PPO 概率比**：对角高斯的 log-prob 按动作维度可分，所以 `r_arm = π(a[0:7]) / π_old(a[0:7])`、`r_base = π(a[7:9]) / π_old(a[7:9])` 可以分别计算、分别裁剪。
- **优势混合**（Deep Whole-Body Control 的 Advantage Mixing）：

  ```text
  A_arm  = A_a + β(s) · A_b
  A_base = A_b + β(s) · A_a
  ```

- **本任务的改动：β 随拦截阶段变化。** 原文的 β 随训练进度从 0 增加到 1。这里用 EKF 预测的“最近接近距离 / 时间”（或方向 1 中到最近 token 的距离）作为阶段变量，例如 `β = sigmoid((d0 − d) / τ)`：离物体远时 β 小，底座主要为接近负责；接近时 β 增大，底座也要为抓取和抬升成功负责（例如学会减速、跟上物体）。
- 和原文一样，这是一种启发式的信用分配，不是无偏的策略梯度。

### 12.3 为什么新颖

- Advantage Mixing 原本用在低层关节空间（腿和臂分开），按训练进度调度。用在高层任务空间（末端增量 + 底座指令）、按拦截阶段调度，是新的组合，也直接对应 DQ-Net 标题里的 whole-body coordination。
- 和方向 7 / GCR-PPO 的区别：方向 7 按奖励组拆 critic，但所有动作仍共用一份合成后的优势；本方向利用的是“哪组动作影响哪组奖励”的因果结构，给不同动作组不同的优势。

### 12.4 代价与风险

- 需要自定义 PPO 损失（skrl PPO 只支持一份优势）；`TSILPPO` 已经有自定义 agent 的先例。
- 分组边界不严格（`approaching` 两组都影响），β 的阶段函数需要调参。
- 如果先做了方向 5（CaT 替代 `command_reward` 的 T/2 开关和 yaw 惩罚），底座组的奖励会更干净。
- 建议记录的诊断：两组动作优势的方差；接近阶段底座速度随距离的变化曲线。

## 13. 方向 11（备选）：多样化的拦截策略

- **现象**：拦截的几何关系（正面迎上、侧面截住、从后追上）难度差别很大。DynaMOMA 报告的成功率分别约为 39% / 62.5% / 91.5%（来自检索，未逐页核对）。单一高斯策略容易收敛到一种拦截方式。
- **做法**：策略额外输入一个隐变量 `z`（例如 4 个离散值），用 DOMiNO 的思路训练：在“接近最优”的约束下最大化不同 `z` 之间的行为差异；测试时用 `V(s, z)` 选价值最高的 `z`。可以和方向 4 的 SAPG 分块合并，每块对应一个 `z`。
- **判断**：故事好，但多样性目标难调，`z` 的选择也需要额外设计，成本和风险都最高，建议在主线完成之后再考虑。

## 14. 组合成论文主线：在哪、何时、多可信、谁负责

| 贡献 | 内容 | 回答的问题 |
|---|---|---|
| C1 表示 | 时空抓取 token（方向 1）+ 事后标注监督（方向 9） | 在哪抓、何时抓 |
| C2 不确定性 | 分段匀速训练 + 实际预测误差特征（方向 8） | 预测有多可信 |
| C3 课程 | 配置库在线演化（方向 3），变异范围扩展到运动参数 | 练什么 |
| C4 全身协调 | 按拦截阶段混合底座/手臂优势（方向 10） | 底座和手臂各负责什么 |

- **主实验**：在 Level02（加分段匀速）上训练，在 Level03 / Level04 上做分布外测试；再逐项去掉 C1–C4 做消融。
- **分析图**：注意力熵与 token 切换率（方向 1）、注意力–不确定性曲线（方向 8）、动态抓取可行性热力图（方向 9）、两组动作的优势方差（方向 10）。
- **提醒**：各方向的新颖性判断只基于这几轮有限的检索，写论文前需要针对每个点做一次系统的文献调研。

## 15. 建议的推进顺序

1. **方向 0**（时间特征进 critic，已实现）和**方向 6**（有色噪声）：改动很小，先建立一个更干净的新基线。
2. **方向 4 的饱和诊断**：只跑 4096 / 8192 / 16384 三组对比，不改代码，决定是否投入 SAPG。
3. **方向 2 的镜像评估**：先检验底层控制器是否大致对称，再上镜像损失。
4. **方向 1**（G1 → G2 → G3）和**方向 9**：两者共用一套 token 代码，是主创新点。
5. **方向 8**：加分段匀速运动和预测误差特征。
6. **方向 3**（先做自生成初态，再做变异；变异维度包括方向 8 的运动参数）。
7. **方向 10**：相对独立，随时可以插入；可以和方向 7 共用多价值头的实现。
8. 视诊断结果再做方向 4、5、7、11。

所有对照都沿用你已有的评估口径：确定性动作、保持 `hold_steps` 才算成功、主指标只看 full_task 类，并在相同训练步数的模型快照上比较。
