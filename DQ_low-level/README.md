# Training a universal low-level policy

## Code structure
`legged_gym/envs` contains environment-related codes.

`legged_gym/scripts` contains train and test scripts.

## Train

The environment related code is `legged_gym/legged_gym/envs/manip_loco/manip_loco.py`, and the related config for b1z1 hardware is in `legged_gym/legged_gym/envs/b1z1/b1z1_config.py`.

```bash
cd legged_gym/scripts
python train.py --headless --exptid SOME_YOUR_DESCRIPTION --proj_name b1z1-low --task b1z1 --sim_device cuda:0 --rl_device cuda:0 --observe_gait_commands
```
- `--debug` disables wandb and set a small number of envs for faster execution.
- `--headless` disables rendering, typically used when you train model.
- `--proj_name` the folder containing all your logs and wandb project name. `manip-loco` is default.
- `--observe_gait_commands` is for tracking specific gait commands and learning the trotting behavior.

Check `legged_gym/legged_gym/utils/helpers.py` for all command line args.

## Play
Only need to specify `--exptid`. The parser will automatically find corresponding runs.
```bash
cd legged_gym/scripts
python play.py --exptid SOME_YOUR_DESCRIPTION --task b1z1 --proj_name b1z1-low --checkpoint 64000 --observe_gait_commands
```
Use `--sim_device cpu --rl_device cpu` in case not enough GPU memory.

## D1 + Piper-L

The added `d1_piper_l` task uses the combined asset in
`resources/robots/d1_piper_l/d1_piper_l.urdf`:

```bash
cd legged_gym/scripts
python train.py --headless --exptid SOME_DESCRIPTION --proj_name d1-piper-l-low \
  --task d1_piper_l --sim_device cuda:0 --rl_device cuda:0
```

Its 22-dimensional policy action is split into 16 D1 leg/wheel outputs and
6 Piper arm outputs.  Hip/thigh/calf outputs are position residuals; the four
wheel outputs are velocity targets (scaled to 5 rad/s) and are converted to
viscous velocity-control torques using the wheel actuator parameters.  The arm
outputs are reserved for the common policy interface and are masked in the
environment.  Piper motion is generated by damped least-squares end-effector
IK and sent to Isaac Gym's position drives.

The Piper task maps the shared command frame into the URDF tool frame with
`q_goal = q_nominal * q_offset`, where the offset RPY is
`[-pi/2, 0, -pi/2]`. This aligns Piper's +Z tool axis with the commanded
forward direction and keeps joint6 centered. It starts from a bent,
nonsingular arm pose, interpolates orientation offsets with the position
trajectory, and uses implicit position-drive gains of Kp=400 and Kd=40.
The Piper effort limits remain `[20, 20, 15, 7, 5, 5]` Nm.

D1 also observes the body-frame quaternion orientation error in the three
previously unused orientation slots and enables orientation tracking reward.
Observation/action dimensions are unchanged, but the observation meanings,
default joint pose, and target distribution have changed. Start a new D1
training run for these settings; old checkpoint quality must be re-evaluated.
B1/Z1 retains its original command-frame mapping, drive gains, and disabled
orientation observation/reward.

To check the actual training targets without loading a policy, run from
`legged_gym/scripts` in the Isaac Gym Python environment:

```bash
python test_d1_piper_l_ik.py --headless --sim_device cuda:0 --pipeline gpu \
  --rl_device cuda:0 --target_mode training --num_envs 32 --duration 30 \
  --warmup 2 --csv /tmp/d1_piper_l_tracking.csv
```

The test uses a fixed base, flat terrain, gravity, and the task's collision
settings. It disables domain randomization and checks every environment
against position RMS <= 3 cm and orientation RMS <= 8 degrees, with no
resets allowed. `--target_mode init_start` and `init_end` hold the configured
initialization targets; `circle` follows a Cartesian circle. `--free_base`
includes base dynamics with zero policy actions, so it is not an evaluation
of a trained locomotion policy. The CSV contains all environments, with
orientation errors in radians.

Kinematic, tool-frame, reset, interpolation, and reward regressions can be
run from `DQ_low-level` without creating a simulator:

```bash
python -m unittest discover -s legged_gym/tests -p test_ee_tracking.py -v
```

## Suggestions
To choose a good low-level policy that can be further used for training the high-level policy, we suggest you deploy the low-level policy first, and see if it goes well before training a high-level policy.
